# claude-dictate

[English](README.md) · Русский

Глобальная голосовая диктовка для Windows на движке распознавания Claude Code.
Нажал Ctrl+Space в любом приложении, сказал, нажал ещё раз, текст вставился
туда, где стоял курсор. Claude Code при этом работает только как «диктофон»:
надиктованный текст перехватывает хук, модель его не получает, токены не
тратятся. Само распознавание бесплатное и в лимиты подписки не входит.

Маленькая утилита на AutoHotkey, без сборки и зависимостей.

## Что нужно

- Windows 10/11.
- [AutoHotkey v2](https://www.autohotkey.com/).
- [Claude Code](https://code.claude.com/) 2.1.116 или новее (нужен tap-режим диктовки),
  `claude.exe` в PATH. Вход через аккаунт claude.ai с подпиской Pro/Max/Team/Enterprise,
  с API-ключом диктовка не работает.
- Микрофон, разрешённый для классических приложений в настройках Windows.

## Запуск

1. Скопируй папку куда угодно.
2. Запусти `dictate-start.ahk` двойным кликом. Откроется свёрнутая консоль с Claude Code,
   в углу экрана появится индикатор `○ ready`, в трее зелёная иконка «H».
3. Первый раз Claude Code в этой папке спросит, доверять ли ей. Разверни консоль
   с панели задач, ответь Yes. Больше не спросит.

Выход: правый клик по индикатору или иконке в трее, `Exit`. Консоль с Claude Code
закроется вместе со скриптом.

## Использование

| Клавиша | Действие |
|---|---|
| Ctrl+Space | начать запись |
| Ctrl+Space ещё раз | остановить и вставить текст в окно, где начинал |
| Escape во время записи | отменить, ничего не вставлять |

Вне записи Escape скрипт не трогает. Буфер обмена после вставки восстанавливается.

Claude Code сам останавливает запись после 15 секунд тишины и после двух минут,
в обоих случаях текст вставляется автоматически. Совсем пустая запись даёт `No speech`.

Индикатор можно перетащить мышью, место запоминается. Правый клик по нему или по
иконке в трее открывает меню: профили (галочка на текущем, клик переключает),
режим окна консоли (скрытое, свёрнутое, видимое), `Autostart` (галочка = ярлык
`dictate-start.ahk.lnk` в `shell:startup`), `Reload`, `Exit`.

| Индикатор | Значит |
|---|---|
| `○ ready` | готов |
| `● REC 1:53` | идёт запись, обратный отсчёт до двух минут, последние 10 секунд красным |
| `… process` | запись остановлена, ждём текст |
| `✓ pasted` | вставлено |
| `✕ ESC` | отменено |
| `No speech` / `No text` / `No mic` / `No Claude` | ошибка, см. `dictate.log` |

## Настройки

Всё в `dictate.ini`, каждый ключ с комментарием: путь к `claude.exe`, режим окна,
положение и прозрачность индикатора, лимиты отсчёта, профили. При первом запуске
файл создаётся из `dictate.example.ini`. После правки `Reload` из меню.

Язык распознавания в `dictate-settings.json`, ключ `language` (по умолчанию `ru`,
список языков в [документации](https://code.claude.com/docs/en/voice-dictation)).

## Файлы

| Файл | Роль |
|---|---|
| `dictate-start.ahk` | **запускать этот**: выбирает профиль и стартует ядро |
| `dictate-core.ahk` | ядро: хоткей, окно Claude Code, индикатор, вставка. Само не запускается |
| `dictate.ini` | настройки; создаётся из `dictate.example.ini`, в git не попадает |
| `dictate-settings.json` | настройки Claude Code для экземпляра диктовки: язык, tap-режим, хук |
| `hook-grab.ps1` | хук: перехватывает промпт, пишет в `dictate-out.txt`, блокирует отправку |
| `dictate.log` | лог: строки хука с распознанным текстом и строки скрипта `[ahk]` |

## Как выбирается профиль

Профиль это папка конфига Claude Code (`CLAUDE_CONFIG_DIR`) со своим логином.

**Один аккаунт, обычный случай.** В `dictate.ini` ключ `dir` в `[profiles]` пустой.
Запускатор сразу стартует ядро с `default`, ядро не трогает `CLAUDE_CONFIG_DIR`,
Claude Code берёт свой обычный `~\.claude`. В меню один пункт `Profile: default`.

**Несколько аккаунтов.** В `[profiles]` указана папка, где на каждый аккаунт своя
подпапка с `.credentials.json`. Запускатор идёт по цепочке и берёт первое, что подошло:

1. Аргумент командной строки: папка конфига или `default`. Так ядро перезапускает
   себя при смене профиля из меню и при `Reload`.
2. Файл из ключа `current`, если в нём записан живой процесс:

   ```ini
   [OpenChamber]
   configDir=C:\path\to\profile
   pid=12345
   ```

   Пока процесс с этим `pid` жив, берётся его `configDir`. Такой файл пишет, например,
   лаунчер OpenChamber, чтобы диктовка шла под тем же аккаунтом, что и он.
3. Ключ `last`: профиль, использованный в прошлый раз. Пишется автоматически.
4. Первая подпапка по алфавиту с `.credentials.json`.

Выбранный профиль записывается в `last` и передаётся ядру. Все профили из папки видны
в меню, клик переключает.

## Как устроено

1. `dictate-core.ahk` запускает `claude --settings dictate-settings.json` в классической
   консоли (не Windows Terminal: он не принимает клавиши, посланные в окно) и шлёт
   туда клавиши через `ControlSend`, не забирая фокус.
2. `dictate-settings.json` включает диктовку в tap-режиме и вешает хук `UserPromptSubmit`.
   Файл передаётся только этому экземпляру, глобальные настройки Claude Code не трогаются.
3. `hook-grab.ps1` получает отправленный промпт, пишет его в `dictate-out.txt` и
   завершается с кодом 2: промпт заблокирован, модель его не видит.
4. Скрипт ждёт файл, вставляет текст через буфер обмена и возвращает старый буфер.
5. Реальное состояние микрофона скрипт читает из реестра Windows
   (`CapabilityAccessManager\ConsentStore\microphone`), иначе пустую запись не отличить.

## Ограничения

- Качество распознавания задаёт сервер Anthropic, повлиять на него нельзя. Русский
  с английскими терминами распознаётся посредственно. Своего словаря у Claude Code нет.
- Только Windows. На macOS схема с хуком повторяется, но вместо AutoHotkey нужен
  Hammerspoon и tmux вместо посылки клавиш в окно.
- Не более двух минут за одну запись, это лимит Claude Code.
